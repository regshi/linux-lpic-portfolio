# サーバー監視の基本

## 目的

Ubuntuサーバーの状態を確認し、CPU、メモリ、ディスク、サービス、ポート、ログを確認する。

インフラ作業では、サーバーが正常に動作しているかを確認し、問題が起きたときに原因を切り分ける力が重要。

## 実行したこと

MacのターミナルからUbuntuへSSH接続し、Ubuntuをサーバーとして扱いながら監視に関する基本コマンドを実行した。

サーバーの状態確認として、稼働時間、メモリ使用量、ディスク使用量、サービス状態、待ち受けポート、ログを確認した。

## コマンド一覧

### UbuntuへSSH接続

```bash
ssh user@192.168.64.3
```

MacのターミナルからUbuntuへSSH接続した。

Macを作業用PC、Ubuntuをサーバーとして扱うことで、実際のインフラ作業に近い形で操作できた。

### 稼働時間と負荷の確認

```bash
uptime
```

サーバーの稼働時間、ログインユーザー数、ロードアベレージを確認した。

ロードアベレージを見ることで、サーバーにどの程度負荷がかかっているかを確認できる。

### メモリ使用量の確認

```bash
free -h
```

メモリの使用量、空き容量、swapの状態を確認した。

`-h` オプションを付けることで、容量が読みやすい単位で表示される。

### ディスク使用量の確認

```bash
df -h
```

ディスク容量の使用状況を確認した。

ディスク容量が不足すると、ログの書き込みやサービスの動作に影響する可能性がある。

### SSHサービスの状態確認

```bash
systemctl is-active ssh
```

SSHサービスが起動しているか確認した。

正常に起動していれば、`active` と表示される。

### Nginxサービスの状態確認

```bash
systemctl is-active nginx
```

Nginxサービスが起動しているか確認した。

Webサーバーが正常に動いているかを確認するために使用した。

### 待ち受けポートの確認

```bash
ss -tuln
```

現在待ち受けているTCP/UDPポートを確認した。

SSHは22番ポート、Nginxは80番ポートで待ち受けていることを確認するために使用した。

### Nginxログの確認

```bash
journalctl -u nginx --no-pager | tail -20
```

Nginxサービスの直近ログを確認した。

`tail -20` を使うことで、ログの最後の20行だけを確認できる。

### SSHログの確認

```bash
journalctl -u ssh --no-pager | tail -20
```

SSHサービスの直近ログを確認した。

SSH接続に問題がある場合、ログを確認することで接続失敗や認証エラーの原因を調べられる。

## 学んだこと

サーバー監視では、CPUやメモリだけでなく、ディスク容量、サービス状態、ポート、ログを総合的に確認する必要がある。

障害対応では、いきなり設定を変更するのではなく、まず現在の状態を確認し、どこに問題があるかを切り分けることが重要。

今回の学習を通して、サーバーが正常に動作しているかを確認するための基本的なLinuxコマンドを整理できた。

また、MacからUbuntuへSSH接続して作業することで、手元のPCからリモートサーバーを操作する流れを実践できた。
