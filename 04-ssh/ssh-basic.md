# SSH基本

## SSHとは

SSHとは、ネットワーク越しに別のコンピュータやサーバーへ安全にログインするための仕組み。

インフラエンジニアは、サーバーに直接画面で触るのではなく、SSHで接続してコマンド操作を行うことが多い。

## SSHでできること

- サーバーへリモートログインする
- サーバー上でLinuxコマンドを実行する
- 設定ファイルを編集する
- ログを確認する
- ファイルを転送する
- サーバーの保守・管理を行う

## 基本的な接続コマンド

```bash
ssh ユーザー名@IPアドレス
```

例：

```bash
ssh user@192.168.1.10
```

GitHubなどに書く場合は、実際のIPアドレスやユーザー名は公開しない。

```bash
ssh user@example-server
```

## SSHでよく使うポート番号

SSHの標準ポート番号は22番。

```text
22/tcp
```

ただし、セキュリティ対策として別のポート番号に変更されている場合もある。

## パスワード認証

ユーザー名とパスワードでログインする方法。

```bash
ssh user@server
```

メリットは簡単なこと。  
デメリットは、パスワードが漏れると不正ログインされる危険があること。

## 鍵認証

秘密鍵と公開鍵を使ってログインする方法。

パスワード認証より安全性が高く、サーバー管理ではよく使われる。

```text
秘密鍵：自分のPCに置く。絶対に他人に見せない。
公開鍵：接続先サーバーに登録する。
```

## SSH鍵の作成

```bash
ssh-keygen
```

作成される代表的なファイル：

```text
~/.ssh/id_rsa      秘密鍵
~/.ssh/id_rsa.pub  公開鍵
```

また、最近では以下の形式も使われる。

```text
~/.ssh/id_ed25519      秘密鍵
~/.ssh/id_ed25519.pub  公開鍵
```

## SSH接続で確認するポイント

SSH接続できない場合は、以下を確認する。

```text
IPアドレスは正しいか
ユーザー名は正しいか
ポート番号は正しいか
サーバー側でSSHが起動しているか
ファイアウォールで22番ポートが許可されているか
秘密鍵の権限が正しいか
ネットワーク疎通があるか
```

## 接続前の確認コマンド

IPアドレスを確認する。

```bash
ip a
```

通信できるか確認する。

```bash
ping -c 4 IPアドレス
```

SSHポートが開いているか確認する。

```bash
ss -tuln
```

## SSHサービスの確認

サーバー側でSSHが動いているか確認する。

```bash
systemctl status ssh
```

または環境によっては、

```bash
systemctl status sshd
```

## SSHの起動

```bash
sudo systemctl start ssh
```

## SSHの自動起動設定

```bash
sudo systemctl enable ssh
```

## ファイル転送

SSHを利用してファイルを送る場合、`scp` を使う。

```bash
scp file.txt user@server:/home/user/
```

サーバーから自分のPCに持ってくる場合：

```bash
scp user@server:/home/user/file.txt .
```

## 注意点

秘密鍵は絶対にGitHubにアップロードしない。

以下の情報は公開リポジトリに載せない。

```text
秘密鍵
パスワード
実際のサーバーIPアドレス
ログインユーザー名
ポート番号
個人情報
```

## 学んだこと

SSHは、Linuxサーバーをリモートから安全に操作するための重要な仕組み。  
インフラ作業では、SSH接続、鍵認証、ポート番号、ファイアウォール、権限設定を理解することが大切だと学んだ。
