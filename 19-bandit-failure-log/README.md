# Bandit 実行失敗ログ

## 目的

OverTheWire Bandit に挑戦しながら、失敗したコマンド・エラー内容・原因・修正方法を記録する。

成功したコマンドだけではなく、なぜ失敗したのかを残すことで、Linuxコマンド、SSH、パス、権限、シェルの理解につなげる。

---

## 記録ルール

- 成功したコマンドは基本的に残さない
- 失敗したコマンドを残す
- エラーメッセージを残す
- なぜ失敗したかを自分の言葉で書く
- パスワードや秘密情報は残さない

---

## Bandit Level 0：SSH接続

### 失敗したコマンド

```zsh
ssh bandit.labs.overthewire.org
```

### エラー内容

```text
Permission denied
```

### 原因

ユーザー名を指定していなかったため、Mac側のユーザー名でSSH接続しようとしていた。

Banditでは、Level 0 のユーザー名として `bandit0` を指定する必要がある。

### 修正の考え方

SSHでは、接続先だけでなく、以下を正しく指定する必要がある。

```text
ssh -p ポート番号 ユーザー名@接続先
```

### 学んだこと

- SSHでは `ユーザー名@ホスト名` の形で接続する
- `-p` は接続先ポート番号を指定するオプション
- Permission denied は、ユーザー名・パスワード・鍵・権限などが原因で出ることがある
- パスワード入力中は画面に文字が表示されない

## Bandit：`-` という名前のファイルを開くときの失敗

### 失敗した内容

Banditで `-` という名前のファイルを開こうとした。

最初は、バッククォートやダブルクォートを使えば開けると思って試した。

### 失敗したコマンド

```zsh
cat `-`
```

```zsh
cat "-"
```

### エラー・うまくいかなかった内容

```text
No such file or directory
```

または、期待したように `-` というファイルを開けなかった。

### 原因

`-` は、多くのコマンドで特別な意味を持つことがある。

特に `cat -` のように書くと、`-` というファイル名ではなく、標準入力として扱われる。

また、バッククォート `` ` ` `` はファイル名を囲むための記号ではなく、コマンド置換に使われる。

そのため、

```zsh
cat `-`
```

は、`-` というファイルを開く意味にはならない。

ダブルクォート `" "` で囲んでも、`cat` にとって `-` は標準入力として扱われるため、目的のファイルを開けなかった。

### 正しい開き方

```zsh
cat ./-
```

### なぜ `./-` で開けるのか

`./` は、現在のディレクトリを表す。

つまり、

```text
./-
```

は、

```text
今いるディレクトリの中にある「-」という名前のファイル
```

という意味になる。

これにより、`-` を標準入力ではなく、ファイル名として指定できる。

### 学んだこと

- `-` はコマンドによって特別な意味を持つことがある
- `cat -` は `-` というファイルを開く意味ではなく、標準入力を読む意味になる
- バッククォート `` ` ` `` はファイル名を囲む記号ではなく、コマンド置換に使う
- ダブルクォート `" "` だけでは、`cat` の `-` の特別扱いを避けられない
- `./-` と書くことで、現在のディレクトリにある `-` というファイルを指定できる


## Bandit Level 2：`--spaces in this filename--` を開くときの失敗

### 状況

Bandit Level 2 で `ls` を実行すると、以下のファイルが表示された。

```text
--spaces in this filename--
```

このファイルを `cat` で開こうとしたが、何度か失敗した。

---

### 失敗したコマンド

```zsh
cat "--space in this filename--"
```

```zsh
cat "space in this failname"
```

```zsh
cat "spaces in this filename"
```

---

### エラー内容

```text
No such file or directory
```

または、

```text
unexpected argument
```

---

### 原因

今回のファイル名には、注意点が2つあった。

```text
1. ファイル名にスペースが含まれている
2. ファイル名が -- から始まっている
```

スペースを含むファイル名は、`" "` で囲むことで1つの引数として扱える。

しかし、今回のファイル名は `--` から始まっているため、`cat` がファイル名ではなくオプションのように解釈しようとした。

また、自分が入力したコマンドでは、ファイル名の一部を間違えていた。

正しいファイル名は、

```text
--spaces in this filename--
```

であり、`space` ではなく `spaces`、最後にも `--` が付いている。

---

### 正しいコマンド

```zsh
cat -- "--spaces in this filename--"
```

または、

```zsh
cat ./"--spaces in this filename--"
```

---

### なぜ `cat --` で開けるのか

`--` は、多くのコマンドで以下の意味を持つ。

```text
ここから先はオプションではなく、引数として扱う
```

そのため、

```zsh
cat -- "--spaces in this filename--"
```

と書くことで、`--spaces in this filename--` をオプションではなくファイル名として扱わせることができる。

---

### なぜ `./` でも開けるのか

`./` は現在のディレクトリを表す。

```zsh
cat ./"--spaces in this filename--"
```

これは、

```text
現在のディレクトリにある「--spaces in this filename--」というファイルを開く
```

という意味になる。

`./` を付けることで、ハイフンから始まる名前でもファイル名として指定しやすくなる。

---

### 学んだこと

- スペースを含むファイル名は `" "` で囲む
- ファイル名が `-` や `--` から始まる場合、コマンドがオプションと勘違いすることがある
- `--` は「ここから先はオプションではない」と示すために使える
- `./` は現在のディレクトリを表す
- ファイル名は正確に入力する必要がある
- `No such file or directory` は、ファイル名の入力ミスでも発生する
